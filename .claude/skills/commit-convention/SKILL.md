# Git commit and branch convention

**Only commit, push or create branches when the user explicitly asks.** Never commit proactively.

## Message format

```
type[/scope[/subscope]][+scope]: summary
```

- **Types (only these):** `feat` · `fix` · `refactor` · `chore`
  - There is no `style` or `docs` type: visual polish is `refactor`, and documentation is `chore/docs`.
- **Scope:** from the allowlist below. Omit it only for genuinely repo-wide changes.
  - **Never invent a new scope.** If none fits, ask the user before adding one to the table.
  - Nested subscope with `/` (`feat/adapters/rss: …`).
  - Combined scopes with `+` when one commit truly spans two (`feat/pipeline+web: …`).
- **Summary:** lowercase first word, imperative mood, no trailing period, about 50 characters or fewer (hard limit about 60).
- **Subject line:** single line by default. Add a body only when the *why* isn't obvious: a blank line, then the body. Prefer `git commit -F <file>` for multi-line messages.
- **Attribution trailers** required by the tooling (e.g. `Co-Authored-By:`) go after a blank line at the end. They are not a body.

## Scope allowlist

The hook reads this table. Add a row here (after asking the user) to allow a new scope.

| Scope | Use for |
|---|---|
| fetch | Polite fetcher: `openroster/fetch.py` (User-Agent, robots.txt, rate limits, cache, budgets) |
| adapters | Source adapters in `openroster/adapters/`. Subscopes: `ics`, `tribe`, `localist`, `jsonld`, `sitemap`, `html`, `headless`, `rss`, `json`, `hackclub`, `manual` |
| extract | Rule-based extraction in `openroster/extract/`. Subscopes: `dates`, `classify`, `geo` |
| pipeline | Normalize, merge/dedupe, archive, run and storage (`openroster/pipeline/`) |
| audit | Source audit and report (`openroster/audit/`) |
| hackathons | Hackathon site checker (`openroster/hackathons.py`) |
| ops | Review, health, selector suggestions, submissions, approvals (`openroster/ops/`) |
| cli | `openroster` command line (`openroster/cli.py`) |
| schema | Opportunity model, exported JSON Schema, data validation (`openroster/model.py`, `schema/`, `openroster/validate.py`) |
| config | Configuration: `config/` (sources, schools, hackathons, verdicts, manual entries, submissions, overrides) and its loader `openroster/config.py` |
| data | Committed data in `data/` (records, archive, audits, health, takedowns, gazetteer) |
| research | Agent research files in `research/` |
| web | Next.js site in `web/`. Subscopes: `filters`, `feeds`, `calendar`, `pages`, `data` (gen-data), `styles` |
| ci | GitHub Actions workflows, issue forms, labels and Dependabot (`.github/`) |
| docs | README, PLAN, decisions, TAKEDOWN, CONTRIBUTING, `docs/` (use with `chore/docs`) |
| tests | Tests and fixtures (`tests/`, `web/tests/`, `web/e2e/`) |
| scripts | Helper scripts in `scripts/` and `web/scripts/` |
| deps | Dependency and lockfile changes (`pyproject.toml`, `uv.lock`, `web/package*.json`) |
| agents | Claude setup: `.claude/` (skills, hooks, settings), `CLAUDE.md`, `web/AGENTS.md` |
| gitignore | `.gitignore` files |

## Examples

```
feat/adapters/rss: add engage rss adapter for brock
fix/extract: stop reading "at" as atlantic time
refactor/web/filters: share filter logic with feed route
chore/docs: document vercel prebuilt deploy
feat/pipeline+web: archive past events and keep their pages
chore/deps: bump next to 16.4.3
chore/gitignore: ignore playwright reports
```

## Branches

`type/scope[-short-slug]`, using the same type and scope as the primary commit, e.g. `feat/adapters-rss`, `fix/extract-atlantic-tz`, `chore/docs-setup`. Use this instead of ad-hoc prefixes unless the user asks for one.

Bot branches created by GitHub Actions (`bot/…`, `ai/…`) are generated by workflows and are exempt. The workflows' commit messages do follow this convention (e.g. `chore/data: update listings`). Dependabot writes its own messages.

## Atomic commits

- Make one coherent change per commit, and split unrelated concerns.
- Stage precise paths (`git add <paths>`), not a blind `git add .` or `git add -A`.

## Safety

- **History:** no history rewrites, force-pushes or `--no-verify`, and don't discard unfamiliar files, unless the user explicitly asks.
- **Secrets:** never commit secrets (`.env*`, tokens, client secrets).
- **Pushing:** don't push unless asked.
- **Git config:** don't change it.

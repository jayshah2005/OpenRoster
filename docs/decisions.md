# Decisions

Each entry gives the choice, the reason, and the alternatives considered. Status is **proposed** until the plan is approved.

| ID | Decision | Reason | Alternatives rejected |
|---|---|---|---|
| D-001 | Python 3.12 for the data pipeline (`openroster` package and CLI); the website is a separate Next.js app in `web/` (D-008) | Strongest free libraries for ICS, JSON-LD, HTML and time zones on the data side | Node for everything (weaker ICS/recurrence tooling) |
| D-002 | Pydantic v2 models as the schema source, exported to JSON Schema and validated in CI | Typed code and a language-neutral schema from one definition | Hand-written JSON Schema (drifts from code) |
| D-003 | Git is the database: one JSON file per record, archive by year, `aliases.json` for merged ids | Free, auditable, reviewable diffs, stable URLs after merges | SQLite in repo (binary diffs); external DB (not free/static) |
| D-004 | A single polite fetcher that every adapter must use: honest UA, ≥ 2 s per host, no per-host parallelism, conditional requests, exponential backoff, per-source page budget, host blocklist enforced in code | One enforcement point for the hard constraints, unit-testable | Per-adapter HTTP code |
| D-005 | `protego` for robots.txt | Implements RFC 9309, including wildcards | `urllib.robotparser` (incomplete wildcard support) |
| D-006 | Rule-based extraction: strict `dateutil` + explicit regex patterns that produce a confidence; anything below "explicit" goes to `needs_review` | The spec forbids guessing; fuzzy parsers like `dateparser` silently guess | `dateparser`; any ML/LLM |
| D-007 | Playwright headless only per source, only when the audit shows JS-only | Free, but slow; keep it rare | Always-headless; paid rendering services |
| D-008 | **Owner choice (2026-10-23): the site is Next.js 16** (App Router, Cache Components). Root layout sets `ensureStatic = "navigation"`, so every page is prerendered and the build fails if one ever needs request-time rendering. A prebuild script turns `data/` and `config/` into JSON modules; client components add filters (URL state), the month grid and the theme toggle; the Suspense fallbacks are the full server-rendered lists, so the site works without JavaScript | Owner asked for Next.js; static output keeps Vercel usage near zero; measured first load 190 kB gzipped (budget 300 kB) | Jinja2 static site (first draft, replaced) |
| D-009 | Feeds per filtered view: Next route handlers `/api/feed.ics` and `/api/feed.rss` apply the same `lib/filter.ts` as the page and send `Cache-Control: s-maxage=21600, stale-while-revalidate=86400`; common feeds (all, each type/role/region/school, type×role, role×region, digest, new today) are prebuilt static files. **Accepted by owner 2026-10-23.** | Exact feeds for every view while CDN caching keeps invocations to a few per distinct filter per day | Prebuild every combination (explodes); snapshot-only (not subscribable) |
| D-010 | Scrape, commit, build and deploy in one workflow run | Commits pushed with `GITHUB_TOKEN` do not trigger other workflows | Separate deploy workflow on push (never fires) |
| D-011 | Bot PRs opened with `GITHUB_TOKEN`, then CI triggered on them through `workflow_dispatch` | `workflow_dispatch` is exempt from the `GITHUB_TOKEN` no-trigger rule, so no App or PAT is needed. Verified in M3; fallback is a free GitHub App. | PAT (personal credential, expires); App up front (manual setup) |
| D-012 | Keepalive: monthly workflow calls the enable-workflow API for each scheduled workflow | Resets the 60-day inactivity timer without dummy commits | Empty "keepalive" commits (noisy history) |
| D-013 | ruff, mypy, pytest with saved fixtures, lychee, axe-core via Playwright | Free and fast in CI | Network tests (flaky, impolite) |
| D-014 | Recurring events: one record per occurrence, linked by `series_id`, expanded 120 days ahead | Each occurrence can be filtered, cancelled or moved on its own | One record per series (breaks date filters) |
| D-015 | A record missing from its only source becomes `needs_review` after 2 consecutive misses, not deleted | A transient source error must not delete data | Delete on first miss |
| D-016 | Dedupe: UID/canonical URL first, then same date ±1 day + place + rapidfuzz title ≥ 90; 80–90 go to review | Deterministic and explainable without an LLM | Embedding similarity (needs AI) |
| D-017 | Source approval is the merge of a bot-generated "Source review" PR that sets `reviewed: true` | Keeps the human decision the spec requires while cutting it to one click | Manual config editing |
| D-018 | Takedown: every takedown issue immediately opens a removal PR (listing id or domain into `data/takedowns.json`); a person merges it; reminders at 24 h and 40 h; blocked items are never collected again | A GitHub issue cannot prove who sent it, so the earlier "auto-hide when the domain matches" idea is not safe; a PR plus reminders still meets 48 h | Auto-hide on claimed domain (spoofable); manual only (missed SLAs) |
| D-019 | Discovery workflow proposes new sources found only on allowed, reviewed pages (calendar embeds, iCal links, platform endpoints) | Grows coverage automatically while staying inside the audit gate | Crawling directories (spec forbids for hackathon seeding; terms risk) |
| D-020 | **Spec change (owner, 2026-10-23):** runtime AI is allowed as an advisory layer only. `anthropics/claude-code-action` with the owner's `CLAUDE_CODE_OAUTH_TOKEN`; no web tools, no merge rights, turn and run budgets; output is always a PR or comment a human merges; AI-derived fields are marked `ai_suggested`; the rule-based pipeline runs fine without the token. | Handles triage, selector repair and summaries that rules do poorly, without breaking "never guess dates", polite fetching or human sign-off | Rules only (more manual review); AI on the publishing path (would publish unverified guesses) |
| D-021 | Region codes use ISO 3166-1/3166-2 (`CA`, `CA-ON`, `US-NY`) | Unambiguous and filterable | Free-text province names |
| D-022 | Host on Vercel Hobby: Actions runs `vercel build` + `vercel deploy --prebuilt` (Vercel CLI pinned in `web/package-lock.json`) | Owner's choice; prebuilt deploys use zero Vercel build minutes; about 4 deploys a day | Vercel git builds (uses build minutes); GitHub Pages (no feed function) |
| D-023 | Location from a bundled offline gazetteer (GeoNames cities15000, CC-BY attribution on About page); "near school" = distance from campus coordinates; coverage rolled out in tiers starting from Brock/Niagara | Owner wants filters based on where events happen; no geocoding API means no rate limits, cost or terms risk | Nominatim (usage-policy limits); school = whichever site it was scraped from (misleading) |
| D-024 | `rss` adapter (Campus Labs Engage `<events:start>` fields, h-event microformats, else rule-based text) and a configurable `json` adapter (field paths; WordPress REST pagination) | Brock's main calendar (ExperienceBU) and Sheridan publish Engage RSS; Western publishes a JSON file; Carleton exposes `cu_event` over WordPress REST | Scraping JS-rendered Engage pages; Engage JSON API (disallowed by robots.txt) |
| D-025 | The fetcher honours robots.txt `Crawl-delay` when it is longer than 2 s (capped at 120 s) | Several Ontario universities ask for 10–60 s | Ignore Crawl-delay (impolite) |
| D-026 | Health state stores dates and capped counters only, and timestamps on records advance at most once a day | A quiet scrape must produce no commit ("commit only when data changes") | Full timestamps (a commit every 6 hours) |
| D-028 | Weekly discovery (`discover.yml`): rule-based `openroster discover` (feeds the audit found on allowed pages, hackathon sites already in the data) plus an optional AI agent that may use web search but never fetches pages. Both only edit config files with `reviewed: false` (and AI-suggested events) in one PR | Owner asked for an agent that finds more sources and events every week. Search keeps the agent off third-party sites (our polite fetcher stays the only thing that requests their pages), and the audit and sign-off gates stay in place | Agent that fetches pages itself (would bypass the polite fetcher and robots checks); fully automatic merge |
| D-027 | Sources whose terms forbid scraping (found by research: Centennial, IGNITE/Humber, MaRS) are excluded from config; sources whose terms only restrict republishing are kept with facts-and-link storage and flagged in the sign-off PR | Matches the spec's audit rule; the owner decides on the restrictive-but-not-forbidding cases | Including everything that technically loads |
| D-029 | The owner approved every source whose latest audit says `allowed` (154) directly on 2026-10-24, instead of merging the Source review PR. Approvals now include disabled HTML sources, so `autoselect` may fetch them once to find selectors | The owner asked for it so the site starts filling. The audit gate is unchanged: blocked sites and MLH stay off, and a source still needs `enabled: true` to run | Waiting for the review PR |
| D-030 | One directory: events and recurring programs in a single list with a left filter column (checkbox groups with live counts, typeable dropdowns for long lists). Programs sort after dated events and are hidden by filters they have no facts for (dates, places, cost). Programs show a drawn monogram, never a logo. Filters the visitor changes are saved in localStorage and restored when a page opens without filters; opening a shared link never overwrites them | A student should see everything in one place and set their preferences once. Logos and images are copied content, which the spec rules out | Separate programs page; real logos; saving whatever view is open |
| D-031 | Deploy through Vercel's GitHub integration (Root Directory `web`, files outside it included) instead of `vercel deploy --prebuilt` from Actions; the Deploy workflow is removed. Supersedes D-022 | Owner wants `main` always in production and every PR deployed for testing. The integration does both with no token, and it sees the data commits Actions pushes. Builds take about a minute, roughly 4 data deploys a day, well inside Hobby limits | Keep the Actions deploy (needs a token, no PR previews) |
